Context Rot Mechanisms

rev 0.1 · notes · ~6 min read

Context rot is not overflow. Overflow is a hard reject. Rot is: the tokens are still in the prompt, and the model uses them worse. Gradient, not cliff.

The window is a working set, not an archive. Everything that is not load-bearing for this step is an adversarial distractor with a softmax vote.

Two failures under one name

POSITION BIAS          LENGTH DEGRADATION
(lost-in-the-middle)   (true rot)

U-shaped recall        quality falls as n grows
same fact, different   even if the fact sits at the end
seat

slot problem           neighbor problem

Chroma (2025) ran 18 frontier models. All of them degrade as input grows. NIAH (exact string needle) lies. Semantic needles, distractors, and coherent haystacks all die faster. A shuffled incoherent haystack beat a coherent one on every model tested — narrative structure is extra noise, not extra signal.

1. Position bias

Start and end survive. Middle dies. 20–30pt drops are normal.

Softmax budget

α_i = exp(q·k_i / √d) / Σ_j exp(q·k_j / √d)

weights on one query sum to 1
add tokens → denominator grows
each relevant token shrinks
SNR falls ~ 1/n when distractors look similar

Sink + recency + dead zone

  • Attention sink / primacy. Softmax must dump mass somewhere. First tokens are always visible. They steal weight even when they carry nothing. Left arm of the U.
  • Causal mask + RoPE recency. Later tokens see more of the sequence and sit closer in rotary space. Right arm of the U.
  • Middle dead zone. Gets neither. Residual paths let the last token teleport. Early tokens compound through layers. Middle tokens take hybrid residual+mix paths and smear.

Pretrain mixes “remember the whole passage” and “use the last thing said.” Those two retrieval demands produce primacy + recency. The U is the compromise.

2. Length degradation

Pin the fact at the end and quality still falls as n grows.

  • more distractors that are semantically close to the answer
  • entropy of the attention distribution rises
  • last-token hidden state collapses toward indistinguishability
  • effective window ≪ advertised window
TASK                 WHEN IT DIES
exact retrieve       late / almost never on frontier
semantic retrieve    ~32K on most models
multi-hop            16–50% of advertised
reasoning            10–20% effective (BABILong)
code bugfix          can collapse (29% @ 32K → 3% @ 256K
                     on one LongCodeBench point)

The “finish inside 50% of the window” rule is too simple. Onset tracks absolute tokens + task type, not a fixed fraction. RULER: many models keep only 16–50% of claimed length.

3. Agent-specific toxins

Transformer bias is the substrate. Long-running agents add four more.

  • Transcript debt. Every tool result stays. A coding session’s window is often ~96% file-read bodies. The first useful read is still present at turn 80 — buried. Prefill cost scales with the pile. Recall of that first read does not.
  • Self-contradiction. Failed attempts, superseded plans, “don’t do X” then “actually do X” sit in one prompt. No pointer to current truth. A weighted soup. Later instructions fight earlier ones for the same softmax mass.
  • State staleness. A task list injected at turn 1 is false by turn 40. The world moved. Context did not. The model treats the stale list as still true because it is still in-window.
  • Compaction loss. Summarize-the-window fires when the window is longest and the model is already weakest. The one warning buried in a debug session is the first thing the summary drops. New window inherits a wrong abstract and treats it as canon.

2026 long-horizon search named a fifth: premature termination. Under long context, models quit or emit an uncertain wrong answer before the window is full. Termination rate tracks context length even with difficulty held fixed. Rot does not only miss facts — it makes the agent stop exploring.

Memory-file drift (MEMORY.md, agent notes) makes rot persistent across sessions: over-summarize nuance away, keep the old preference after you changed it, load both lines. Now the soup survives the session boundary.

What it looks like from outside

SYMPTOM                         MECHANISM
ignores a rule stated at start  that rule slid into the middle
contradicts itself 30 turns later both versions still in-window
re-asks a solved question       earlier answer diluted / compacted out
re-does finished work           no authoritative state; transcript looks open
happy-path “done” then ships a hole  premature stop + no sensor
hallucinates “as we discussed”  generating a reference it cannot use
tool calls get sloppy           schemas + old results vs current goal

Rot ≠ amnesia. The bits are there. The attention budget is not.

Match the lever to the failure

position bias      invariants at head AND tail
dilution           fewer tokens, not smarter retrieval of the same pile
distractors        extract facts, drop dialogue
                   contradiction must block the next step
transcript debt    persist tool bodies to disk, leave a stub
staleness          authoritative state files, not chat history
compaction loss    compact tool results first
                   never let an LLM summary be the only copy of a constraint
premature stop     sensors / tests / “not done until X”
                   do not trust the completion token
session rot        fresh context per execution unit
                   accumulated context only for synthesis

What this is not

X is full of “Anthropic engineer built a memory engine that forgets 90%” posts. Same stencil, unnamed engineer, four ALL-CAPS components, fake 14-day / zero-drift metrics, quote-card pointing at an unrelated article. Steal the verbs (extract, collide, prune, evict). Do not steal the attribution.

What Anthropic actually shipped is boring and real: MEMORY.md with a 200-line cap, Auto Dream between sessions, compaction, skills that load ~2k tokens only on match. File-system memory. Not a 2,000-token invariant graph with a secret pruner.

The idea underneath those posts is still the right idea: context is debt. Keep invariants. Drop transcripts. Force a state clash to halt the next step. Write the surviving rule into the harness — tests, sensors, AGENTS.md — so the agent cannot make the same mistake twice.

For this kernel

Web Agent Machine already treats the tab as a bounded runtime: intent → plan → broker → act. Context rot is the reason that loop must not accumulate tool dumps in the same buffer that holds the goal.

GOAL + CONSTRAINTS     hot, always in-window
CURRENT STEP STATE     hot, file-backed, rewritten not appended
TOOL BODIES            cold, disk / stub
FAILED ATTEMPTS        cold, or one-line dead-end ledger
SESSION TRANSCRIPT     not an archive

If the kernel starts stuffing every FileAgent and BrowserAgent result back into the next plan prompt, it will recreate the same failure the cloud agents already have — only cheaper, and still wrong.
