The CLI Never Died — It Just Got Cross-Platform

rev 0.1 · notes · ~3 min read

A CLI is a text-based environment. You type commands. The machine answers. No mouse, no icons, no visual chrome — just the purest interface we ever built.

Bash (Bourne Again SHell) is the most common interpreter on Linux and historical macOS. It takes the text you type — ls, mkdir, grep — and turns it into system actions. It is also a full scripting language.

A short history

  • 1960s — Teletypes
    Commands typed on a keyboard, answers printed on paper. The original TTY.
  • 1970s — Unix + Bourne shell
    CRT terminals replace paper. Modular commands + pipes. The philosophy that still runs the internet.
  • 1980s — MS-DOS
    The PC gets its own command line. Different verbs (dir instead of ls).
  • 1989 — Bash
    Brian Fox writes a free, feature-rich replacement for the original Bourne shell for the GNU project. It becomes the default on Linux.

The great unification

For decades the command lines were walled gardens. Then the walls fell:

  • PowerShell — Microsoft rewrote it as open-source and cross-platform. Same tool on Windows, macOS, and Linux.
  • WSL — Real Linux (including Bash) running natively inside Windows. No VM tax.
  • Modern CLIs — Git, Docker, AWS CLI, almost everything new is written in Go or Rust. One binary, identical flags, every OS.

Why this still matters for agents

Text is the cheapest, most composable, most capability-securable interface we have. A well-designed CLI is already an agent runtime — just one that humans can also drive. Browser agents, local kernels, and remote tool-using models all inherit the same design pressure: low bandwidth, high precision, explicit verbs.

The shell never died. It just stopped caring which OS you were on.
