Scan-Line to Splat

rev 0.1 · notes · ~8 min · 1967 → web GPU

A 3D object on a screen is never the object. It is a representation plus an algorithm that turns that representation into ordered fragments. The calculus does not change. The storage of the surface does.

This line starts at Utah scan-line shading in 1967 and ends in the tab: WebGL, WebGPU, ASCII projection, 3D/4D Gaussians. Same pipeline pressure the whole way — visibility, interpolation, light.

1967 — the scan-line object

Wylie, Romney, Evans, and Erdahl, University of Utah, AFIPS Fall Joint Computer Conference: Halftone Perspective Drawings by Computer. Not a modern GPU. A shaded polygon projected in perspective and filled one horizontal row at a time.

Watkins (Utah PhD, 1970) makes the algorithm operational for real-time visible surface: keep an active-edge table, walk y, fill spans. Bouknight and others close the shading loop in the early 70s. “Scan-line rendering in 1967” is the Utah cluster, not a single trademarked routine.

Object

A polyhedron. Vertices in world space. Faces as ordered rings. No textures yet. No normals per vertex until Gouraud.

Algorithm

project vertices  →  (x/z, y/z)
bucket edges by y_min
for y in [ymin .. ymax]:
  insert / retire edges
  sort active edges by x
  pair them into spans [xL, xR]
  for x in span:
    write shade(x, y) if this face is front

Visibility is solved on the line: depth at the span, or a list of fragment intervals. You never hold a full image-space z pyramid. Memory in 1967 cannot afford Catmull’s later buffer.

Calculus

perspective
  x_s = f · X / Z + c_x
  y_s = f · Y / Z + c_y

edge walk (DDA)
  x(y+1) = x(y) + Δx/Δy

attribute on a span  (affine, the 1967–71 default)
  C(x) = (1-t) C_L + t C_R
  t    = (x - x_L) / (x_R - x_L)

perspective-correct form  (later, required for texture)
  C =  [(1-t) C_L/Z_L + t C_R/Z_R]
     / [(1-t)     1/Z_L + t     1/Z_R]

why the divide:
  linear interpolation in screen space ≠ linear in world space
  1/Z is the quantity that *is* linear after the projective map

That last identity is projective geometry, not a GPU trick. Homogeneous [X Y Z W] with W = Z after the camera transform is the same statement: divide after you interpolate.

1971–75 — the shaded mesh

Gouraud (1971): compute irradiance at vertices, interpolate the color across the scan. Cheap. Mach bands at silhouettes.

Phong (1975): interpolate the unit normal, renormalize, evaluate the lobe per pixel.

I = k_a I_a
  + k_d I_d max(N·L, 0)
  + k_s I_s max(R·V, 0)^n

R = 2 (N·L) N − L
N, L, V unit

Catmull 1974: z-buffer + texture mapping. Visibility leaves the edge table and becomes a per-pixel compare. Sutherland, Sproull, Schumacker the same year classify ten hidden-surface algorithms — scan-line is one family, image-precision z is another, list-priority (Newell painter) a third.

z-buffer
  if z_frag < zbuf[x,y]:
    zbuf[x,y]  = z_frag
    color[x,y] = shade(frag)

Object is still a triangle mesh. The algorithm moved from “sort the world per row” to “test each fragment against a screen-sized memory.” That trade only becomes free once memory is cheap. On the web it is free. On a 1967 machine it was not.

1980–86 — leave the raster

Whitted 1980: the primary ray hits, then spawn reflection / refraction / shadow rays. The object is still triangles (or quadrics). The algorithm is a tree of intersections, not a span.

Kajiya 1986 writes the thing every later method is approximating:

L_o(x, ω_o) = L_e(x, ω_o)
  + ∫_Ω f_r(x, ω_i, ω_o) L_i(x, ω_i) (ω_i · n) dω_i

That is a hemisphere integral. Scan-line Phong is a one-sample estimate of it (directional light + a fake specular lobe). Path tracing is Monte Carlo on the same integral. Radiosity discretizes the geometry and solves a linear system. Nothing after 1986 invents a new light transport law. It invents samplers.

Other objects in the same decade

  • Parametric patches — Bézier / B-spline / later NURBS. Object is a map [0,1]² → R³. Render by recursive subdivision until a patch is flat enough to be a polygon, or ray-patch invert.
  • Implicits / voxels — Marching Cubes (Lorensen & Cline, 1987) turns a scalar field f(x)=0 into triangles. The mesh is now a derived view of a volume.
  • Points — already a research primitive; they come back as the web’s cheapest 3D (and as Gaussians).

1992–2009 — API, then the web’s first try

1992   OpenGL 1.0          fixed function: matrix stack + scan convert
1993   Doom BSP            object-space partition, painter in 2.5D
1996   Quake               software raster + PVS, then GLQuake
1995   VRML                scene graph over HTTP. Plugin era.
2001   programmable GPU    vertex + fragment replace the fixed stack
2006   Canvas 3D experiments in browsers
2011   WebGL 1.0           OpenGL ES 2.0 in the tab. No plugin.

VRML failed as a product and succeeded as a warning: a web 3D object that needs a binary plugin is not a web object. WebGL wins because the rasterizer is already in the process.

2011–17 — the web mesh

Three.js (2010) wraps the raw GLES state machine so a page can hold a scene graph again without writing a driver. glTF later becomes the interchange mesh: attributes, accessors, PBR metallic-roughness.

MVP chain  (column vectors, GL convention)
  clip   = P · V · M · [x y z 1]ᵀ
  ndc    = clip.xyz / clip.w
  screen = 0.5 · (ndc.xy + 1) · viewport

vertex shader   = the 1967 project step, now a program
rasterizer      = the scan converter, now fixed silicon
fragment shader = Phong / Cook-Torrance / PBR, per pixel

Cook-Torrance / Disney / glTF PBR replace Phong’s (R·V)^n with a microfacet integral:

f_r = k_d / π +  D F G  /  (4 (n·ω_i)(n·ω_o))

D  GGX normal distribution
F  Fresnel (Schlick)
G  geometry / shadowing-masking

Still Kajiya. Still one or two samples of the sun, plus an IBL integral baked into an irradiance cube and a prefiltered specular lod. The calculus hid in the mip chain: dFdx / dFdy pick the lod so the texture integral matches the pixel footprint — the same 1/Z correctness problem, now in filter space.

Pedagogical object: the torus

a1k0n’s 2011 donut is the scan-line idea stripped to projection + z-buffer + a luminance character. No GPU. Same math the Utah group used on paper.

torus sample
  x = (R2 + R1 cos θ) cos φ
  y =  R1 sin θ
  z = (R2 + R1 cos θ) sin φ
then rotate by A (X), B (Z)

ooz = 1 / (K2 + z)          // 1/Z again
x'  = K1 · ooz · x
y'  = K1 · ooz · y
L   = N·light
keep sample if ooz > zbuf[x',y']

That is the training-wheels object for this repo: surface samples → project → visibility. Gaussian splats are the same sentence with a covariance instead of a character.

2017–22 — WebGL 2, then WebGPU

WebGL 2 (2017) is ES 3.0: VAOs, instancing, 3D textures, GLSL 300. Enough to ship a serious rasterizer. Not enough to write your own compute sort without hacks.

WebGPU is the second web graphics epoch. Compute shaders, explicit pipelines, WGSL. The scan converter is still there if you draw triangles. You can also skip it and splat.

2020–26 — fields, then blobs

NeRF (2020): the object is an MLP F_θ(x, d) → (σ, c). The algorithm is quadrature along a ray — Kajiya with a learned density. Beautiful. Too heavy for a phone tab without distillation.

3D Gaussian Splatting (Kerbl, Kopanas, Leimkühler, Drettakis, 2023): the object is a bag of anisotropic 3D Gaussians.

G(x) = exp( −½ (x − μ)ᵀ Σ⁻¹ (x − μ) )

Σ = R S Sᵀ Rᵀ
  S = diag(s_x, s_y, s_z)
  R from a unit quaternion

project to 2D covariance  (Zwicker EWA)
  Σ' = J W Σ Wᵀ Jᵀ
sort by depth, α-blend
  C = Σ_i  c_i α_i  Π_{j
    
No triangle. No scan-line edge table. Visibility is a sort plus front-to-back compositing — Porter-Duff 1984, running on a million blobs. The derivative that trains the blob (position, scale, quat, SH color, opacity) is just reverse-mode on that project-and-blend.


    
4DGS splits in two families:

    
    
      
  • Deformation (Wu et al., 2024) — canonical 3D Gaussians + a HexPlane-style field that warps μ(t). Smaller to ship.
    • 
      
  • Native 4D (Yang et al.) — μ and Σ live in (x,y,z,t). Condition on t to recover a 3D Gaussian. Heavier, more honest about motion covariance.
    • 
    

    
native 4D condition
  μ_xyz|t  = μ_1:3 + Σ_1:3,4 Σ_4,4⁻¹ (t − μ_t)
  Σ_xyz|t  = Σ_1:3,1:3 − Σ_1:3,4 Σ_4,4⁻¹ Σ_4,1:3

    
That is a Gaussian conditional, not a graphics invention. Same linear-algebra move as a Kalman update.

What the calculus actually is

    
    
      
  • Projective divide. 1/Z is linear in screen space. Interpolate that, not the world attribute. 1967 already needed this. Texture mapping made it non-optional.
    • 
      
  • Convex combination. A scan span, a barycentric triple, a mip footprint — all integrals of a function against a kernel supported on the pixel.
    • 
      
  • Hemisphere integral. Kajiya. Every real-time shade is a 1-sample or pre-integrated stand-in.
    • 
      
  • Chain rule. Vertex → clip → ndc → screen. Fragment → BRDF. Splat → 2D Σ → α → color. Training a Gaussian is autodiff through the 1967 projection.
    • 
      
  • Conditioning. 4D → 3D Gaussians. Linear algebra, not a shader trick.
    • 
    


    
For this kernel

    
Web Agent Machine already treats the tab as a bounded runtime. Graphics is another capability, not a CDN of screenshots.

4D deformation field     ship the small canonical set
native 4D                only after prune + quantize

    
Do not start at 4DGS. Start at the 1967 sentence: sample a surface, project by 1/Z, keep the nearest, shade. The torus does that in a 
. The Gaussian does that with a covariance. The agent should know which object it is holding before it asks the GPU for a pipeline.
