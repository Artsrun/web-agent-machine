The Agent Loop Hidden in Plain Sight

rev 0.1 · notes · ~5 min read

There is still no universal “AI Agent Standard.” Humanity has not managed to agree on one protocol for making software think. What we do have are increasingly stable patterns. A Grok investigation sequence makes them visible.

What the sequence actually did

User task
   │
   ▼
Discover skills / design-ui/...
   │
   ▼
Read domain guidance
  refined-ui.md · typography.md · surfaces.md
   │
   ▼
Inspect target
  auth/gates.tsx
   │
   ▼
Expand context
  /src/lib
   │
   ▼
Read dependency
  auth/client.ts

It did not open the target file first. It asked, effectively: “What rules do I need before I touch this?” That is context acquisition, not code generation.

Skills vs Tools

A tool answers how can I perform an operation?
A skill answers how should I perform this class of operation?

read_file() is a tool. design-ui is a skill — principles, constraints, patterns, anti-patterns, validation rules. The separation is powerful:

        AGENT
          │
    ┌─────┴─────┐
    │           │
  TOOLS       SKILLS
    │           │
   HOW         HOW
    │           │
    └─────┬─────┘
          ▼
       ACTION

The fundamental loop

         GOAL
           │
           ▼
        OBSERVE
           │
           ▼
         PLAN
           │
           ▼
          ACT
           │
           ▼
     OBSERVE RESULT
           │
      success?
     /        \
   no          yes
   │            │
 REPLAN       VERIFY
   │            │
   └────┐       ▼
        │     DONE
        └───────►

Modern agents rarely generate a 47-step plan and then march into a wall. They interleave plan → act → observe → re-plan. The second approach is how you get confident failure that lasts eleven minutes.

Capability layers

  • Layer 0 — Model
    Understands, reasons, generates. Alone it is a brain in a jar.
  • Layer 1 — Context
    read / search / retrieve / remember / inspect
  • Layer 2 — Tools
    Filesystem, terminal, browser, git, API, calculator…
  • Layer 3 — Skills
    Normative knowledge for a class of work.
  • Layer 4 — Memory
    Working, episodic, semantic, procedural — externalized as AGENTS.md, skills/, git history, previous attempts.
  • Layer 5 — Planning
    Goal decomposition that stays adaptive.
  • Layer 6 — Verification
    ACTION ≠ SUCCESS. Lint, typecheck, test, inspect diff, run the thing.
  • Layer 7 — Recovery
    Retry, rollback, alternative strategy, reduce scope, escalate.
  • Layer 8 — Governance
    Can I read / write / execute / call external / delete?

A minimal capability contract

AGENT
├── INPUT        goal · constraints · context
├── DISCOVERY    skills · tools · resources · capabilities
├── CONTEXT      retrieve · search · read · memory
├── REASONING    analyze · plan · prioritize · decide
├── EXECUTION    tool_call · file_op · API · code
├── OBSERVATION  result · error · state · environment
├── VERIFICATION test · validate · compare · inspect
├── RECOVERY     retry · replan · rollback · escalate
└── OUTPUT       result · evidence · changes · status

This is a useful yardstick for comparing Grok, Claude Code, Codex, OpenCode, Cursor agents, or any local kernel you build.

The bigger shift

Chatbot → Tool-using LLM → Agent → Multi-agent system → Agentic runtime.

An LLM knows things. A tool-using LLM can do things. An agent decides what it needs to do, does it, inspects the result, and continues. An agentic runtime operates inside a defined environment with tools, memory, skills, policies, and verification loops.

The Grok sequence is the missing middle layer made visible: the agent builds its world model before it touches the world.
